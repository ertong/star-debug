The Android 1.2b83 release was built in the Docker image `ertong/flutter:3.50.1-api37-jdk25`
(Flutter 3.50.1, Android API 37, JDK 25, Ubuntu 26.04), published on Docker Hub.

The repository now keeps that image's Dockerfile in `_build/docker/`; it was added after the
release tag. To build an equivalent image yourself instead of pulling it:

```bash
docker build -t star-debug-ci:1.2b83 \
    "https://github.com/ertong/star-debug.git#95ff23d6ffac335027b7de2b6deae7a72edeefbe:_build/docker"
```

It installs the same Flutter release, Android SDK packages, and JDK from a fixed Ubuntu archive
snapshot; only `ca-certificates` and `platform-tools` come in at their current versions. To use it,
run the script below with `IMAGE=star-debug-ci:1.2b83` set in the environment.

Use the following script to start the image:

```bash
#!/bin/bash

DIR="$(cd "$(dirname "$0")" && pwd)"
IMAGE="${IMAGE:-ertong/flutter:3.50.1-api37-jdk25}"
CI_PROJECT_DIR=/builds/ertong/star-debug-ci
docker run --rm -it -v "$DIR/star-debug:$CI_PROJECT_DIR" \
    -e ANDROID_KEY_PASSWORD=pass123 \
    -e NAME=1.2.83a \
    -e NUM=83 \
    -e BUILD_OPTS="--build-name=1.2.83a --build-number=83" \
    -e LC_ALL=en_US.UTF-8 \
    -e LANG=en_US.UTF-8 \
    -e PUB_CACHE="${CI_PROJECT_DIR}/.cache/.pub-cache" \
    -e GRADLE_USER_HOME="${CI_PROJECT_DIR}/.cache/.gradle" \
    -w "$CI_PROJECT_DIR" \
    "$IMAGE"
```

Inside the container, run:

```bash
git clone --branch 1.2b83 https://github.com/ertong/star-debug.git .
cd star.debug
keytool -genkey -v \
    -keystore ./android/release-key.jks \
    -alias key \
    -keyalg RSA \
    -keysize 2048 \
    -validity 10000 \
    -keypass pass123 \
    -storepass pass123 \
    -dname "cn=Test, ou=Test, o=test, c=UA"
flutter build apk $BUILD_OPTS
```

The result is `build/app/outputs/flutter-apk/app-release.apk`, signed with the generated test key.
The signature will differ from the store build; compare the application code and native libraries as
described in the [reproducible-build overview](reproducible_builds.md).

Use the following script to start the same Docker image used to build the Android 1.2b79 release:

```bash
#!/bin/bash

DIR="$(cd "$(dirname "$0")" && pwd)"
CI_PROJECT_DIR=/builds/ertong/star-debug-ci
docker run --rm -it -v "$DIR/star-debug:$CI_PROJECT_DIR" \
    -e ANDROID_KEY_PASSWORD=pass123 \
    -e NAME=1.2.79a \
    -e NUM=79 \
    -e BUILD_OPTS="--build-name=1.2.79a --build-number=79" \
    -e LC_ALL=en_US.UTF-8 \
    -e LANG=en_US.UTF-8 \
    -e PUB_CACHE="${CI_PROJECT_DIR}/.cache/.pub-cache" \
    -e GRADLE_USER_HOME="${CI_PROJECT_DIR}/.cache/.gradle" \
    -w "$CI_PROJECT_DIR" \
    ertong/flutter:3.47.0-api36-jdk17
```

Inside the container, run:

```bash
git clone --branch 1.2b79 https://github.com/ertong/star-debug.git .
cd star.debug
keytool -genkey -v \
    -keystore ./android/release-key.jks \
    -alias key \
    -keyalg RSA \
    -keysize 2048 \
    -validity 10000 \
    -keypass pass123 \
    -storepass pass123 \
    -dname "cn=Test, ou=Test, o=test, c=UA"
flutter build apk $BUILD_OPTS
```

The result is `build/app/outputs/flutter-apk/app-release.apk`, signed with the generated test key.
The signature will differ from the store build; compare the application code and native libraries as
described in the [reproducible-build overview](reproducible_builds.md).
